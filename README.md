# beleg-pipeline

A document pipeline that turns a year of unsorted rental property paperwork into a checked,
categorized cost overview per apartment, with a human confirming anything uncertain.

**The AI reads, code checks, a human decides.**

> Status: **Stage 1 (ingestion) in progress.** Acceptance tests define done; see below.

## Why

Landlords, property managers and small businesses receive invoices, statements and contracts
from many senders in many formats. Sorting, assigning and checking them is manual, slow and
error-prone. This project builds the pipeline end to end on real-world, messy German documents,
with measurable accuracy and GDPR-compliant handling.

## Pipeline

| # | Stage | Who | Status |
| --- | --- | --- | --- |
| 1 | **Ingest** – accept, store original, register | Code | 🚧 in progress |
| 2 | Read – text layer or OCR | Code | planned |
| 3 | Classify – document type | LLM | planned |
| 4 | Extract – fields with evidence | LLM | planned |
| 5 | Validate and categorize | Code | planned |
| 6 | Route – auto-accept or review | Code | planned |
| 7 | Human review | Human | planned |
| 8 | Export and audit | Code | planned |

## Stage 1: ingestion

Accepts every document from every channel, stores the original unchanged and registers it with
a stable ID. No OCR, no AI. Details: [`docs/architecture.md`](docs/architecture.md) and the
decisions in [`docs/adr/`](docs/adr/).

```text
src/ingest/
├─ domain/      pure rules and models, no I/O          (unit-tested)
├─ ports/       interfaces the core depends on
├─ service/     IngestionService: the 8-step sequence
├─ adapters/    file system, SQLite, file inspection, folder watcher
├─ config.py    settings from .env (prefix INGEST_)
└─ cli.py       `ingest` command; wires adapters into the service
```

## Quick start

Requires Python 3.12 and [uv](https://docs.astral.sh/uv/).

```bash
uv sync                      # create venv and install
cp .env.example .env         # adjust paths if needed
uv run pytest tests/unit     # rules: green
uv run pytest -m acceptance  # stage 1 definition of done
uv run ingest run-once       # process everything in data/inbox
uv run ingest watch          # keep watching the inbox
uv run ingest quarantine     # list files that need attention
uv run ingest verify         # re-hash all stored originals
```

With Docker:

```bash
docker build -t beleg-pipeline .
docker run --rm -v "$(pwd)/data:/app/data" beleg-pipeline run-once
```

## Acceptance tests (stage 1)

- [ ] 12 valid PDFs and images become 12 `received` documents
- [ ] The same file twice gives one document and one `DuplicateDetected` event
- [ ] A JPG renamed to `.pdf` is detected by content and accepted
- [ ] A password-protected PDF is quarantined (`encrypted`)
- [ ] A truncated PDF is quarantined (`corrupt`)
- [ ] ZIP and EXE are rejected (`unsupported_type`)
- [ ] A 60 MB file is quarantined (`too_large`)
- [ ] An iPhone HEIC photo is converted and its original kept
- [ ] A second run over the same folder adds nothing
- [ ] An orphan blob after a crash is recovered by the sweep
- [ ] Every stored blob re-hashes to its SHA-256

Test files are generated by [`tests/fixtures/make_fixtures.py`](tests/fixtures/make_fixtures.py);
no binary or real documents are committed.

## Data protection

- Real documents and the database live in `data/`, which is git-ignored. Never commit them.
- Phase 1 makes no network calls; nothing leaves the machine.
- Originals are stored read-only and verified by hash; every outcome is logged as an event.
- A pre-commit hook blocks files over 500 KB to stop scans being committed by accident.
